# 02 · Architecture

The site uses no framework: a single Node script generates static HTML. The only runtime dependencies are self-hosted GSAP, ScrollTrigger and Lenis.

## Commands
| Command | What it does |
|---|---|
| `npm install` | Installs the build tools: esbuild (minifies CSS/JS), sharp (images), playwright-core (screenshots), the font packages. |
| `node build.mjs` / `npm run build` | Writes `dist/`: 18 HTML pages, sitemap.xml, llms.txt and the assets. CSS and JS are minified. |
| `node serve.mjs` / `npm run dev` / `start.bat` | Local server at http://localhost:4321 with clean URLs (`/fr/contact` serves `dist/fr/contact.html`). It serves `dist/`, so rebuild after every edit. |
| `node scripts/shoot.mjs <outdir> [paths]` | Takes desktop and mobile screenshots. Needs Chromium; the script points `executablePath` at the cloud container's path, `/opt/pw-browsers/chromium`. On a PC, change that line or run `npx playwright install chromium`. |

## How `build.mjs` is organised
1. **Data.** Imports from `src/content.mjs` and reads the three JSON manifests.
2. **Helpers:**
   - `esc` escapes HTML; `pad` gives two-digit numbers.
   - `mark()` draws the logo mark; `pic()` outputs a responsive project image; `evImg()` outputs an event photo.
   - `socialIcon` holds the social SVGs; `sun` and `moon` are the theme icons.
3. **Schema.**
   - `orgSchema` is the Organization/ProfessionalService record, with the Marseille and Doha places, areaServed and sameAs.
   - Also `websiteSchema`, `faqSchema()` and `crumbs()` (breadcrumbs).
4. **Shared page parts:**
   - `floating()`: the fixed rails, the theme switch, the socials, and the two floating buttons (WhatsApp, "Parlons de votre projet").
   - `header()` with `navLinks`, and `footer()`: CTA panel, offices column, animated "codex" letters.
   - `layout()`: head meta, canonical, hreflang, geo meta, JSON-LD, loader, page-transition panel, cursor, grain.
5. **Section builders**, each a function returning HTML:
   - `faqBlock`, `marqueeBlock`, `statsBlock`, `processBlock`
   - `eventsBlock`: event list, pinned deck with 2 photos per event, hover trail
   - `reasonsBlock`, `sectorsBlock`, `veloBlock`, `techBlock`
   - `projectCard` / `workBlock`: horizontal pinned carousel
   - `clientsBlock`: the logo band (see below)
   - `testimonialsBlock`: certificate stack and quotes
   - `serviceRows`
   - `reelBlock`: no longer used.
6. **Pages.** A `pages` array; each entry has `{file, path, title, desc, schema, current, body}`. The pages are:
   - `/fr`: home.
   - `/fr/services` and 8 service pages under `/fr/services/<slug>`.
   - `/fr/realisations`: projects, with filters and a lightbox.
   - `/fr/evenements`: photo gallery, with filters and a viewer.
   - `/fr/attestations-bonne-execution`: testimonials stage and the certificate grid.
   - `/fr/agence`, `/fr/contact`.
   - `/fr/merci`, `/404`: both noindex.
   - `index.html`, which redirects to `/fr`.
7. **Write.**
   - Copies `src/assets` and `src/public`, minifies main.css and main.js with esbuild, and writes the pages.
   - Writes `sitemap.xml`, which includes images.
   - Writes `llms.txt`, a plain summary for AI assistants.

### Logo band (clientsBlock)
- `logoSize(id)` gives every logo the same visual area, using the aspect ratio from `src/clients.json`.
- Each logo is an `<i class="lmark">` painted with a CSS `mask` (the `-m.webp` silhouette), so it takes the theme colour.
- Each row has two tracks: the grey base track, and an identical track inside `.lband__glow`, painted in the accent colour.
- `.lband__glow` has a radial `mask-image` placed at `--gx/--gy/--r`; that mask is the spotlight.

### Testimonials (testimonialsBlock)
- Quotes come from `testimonials` in `src/content.mjs`.
- `hlQuote()` wraps the `hl` phrase in `<mark class="tst__hl">`.
- `clientMask()` and `clientLogo()` find a logo (exact id, or the `logoAlias` map). Without one, `initials()` builds a monogram.
- The stage holds three parts: the stack of `certificates/<cert>-480.webp`, the `stamp` SVG, and the thumbnails with SVG progress rings.

## Languages (FR / EN / AR)
- Same slugs in every language, only the prefix changes: `/fr/agence`, `/en/agence`, `/ar/agence`. French is the reference.
- Content: `src/content.en.mjs` / `content.ar.mjs` and `src/blog.en.mjs` / `blog.ar.mjs` import the French module and override the text. **When you add or change French content, add the same item to the EN and AR files.** Event names are mapped with `eventLabel`.
- `build.mjs` renders every page three times through `render(LANG)` (the templates are still written in French). For EN and AR, `localize()` then:
  1. translates the remaining interface phrases with `src/i18n.mjs` (`HTML` for headings with an `<em>`, `TEXT` for whole text nodes / attributes / JSON-LD strings, `RULES` for phrases built around a name or number);
  2. rewrites `/fr` links to `/en` or `/ar`;
  3. replaces the `__L:xx__` placeholders (language switcher and hreflang).
- **The build prints "Untranslated French phrases"** when a new French template string reaches an EN/AR page: add a row to `src/i18n.mjs`.
- Arabic: `<html lang="ar-DZ" dir="rtl">`, IBM Plex Sans Arabic (self-hosted, `src/assets/fonts/ibm-plex-sans-arabic-*.woff2`, from `@fontsource/ibm-plex-sans-arabic`), no letter-spacing and no italics (the letters must stay joined). `main.js` animates Arabic text word by word, skips the eyebrow scramble, and has its runtime strings in `T`. RTL rules are at the end of `main.css`.
- One 404 page (French). The sitemap lists every language with `xhtml:link` alternates; `llms.txt` stays French and lists the language versions.

## `main.js` structure (in file order)
- **Setup:**
  - Helpers: `$`, `$$`, `yieldTask` (splits setup into small tasks).
  - `fine`: true if any fine pointer is available (`any-hover` / `any-pointer`).
  - `whenMouse(fn)`: runs mouse effects only once a real mouse is detected.
  - `onView` / `playOnView`: one shared IntersectionObserver for one-shot reveals.
- **Motion modules, top to bottom:**
  - smooth scroll (Lenis, desktop/mouse only)
  - text splitting (accessible: an sr-only copy plus an aria-hidden visual copy)
  - loader and intro
  - scroll reveals (a different entrance per kind of element)
  - marquee: all tracks in a row move together; speed follows scroll velocity, direction follows scroll direction; logo rows slow under the cursor
  - logo band spotlight
  - horizontal work scroll
  - nav; cursor, magnetic buttons, service preview
  - FAQ; footer clock; contact form (mail fallback when `data-form-mode="mail"`)
  - theme switch (view-transition circle)
  - page transitions; scroll progress; hero exit; rotating word; eyebrow scramble; inverted sections; velocity rows; footer wordmark; image reveals; hero dot field (canvas); 3D tilt; reel; portfolio filters; lightbox
  - **v3 layer:** odometers, button text roll, SVG illustrations drawing, hairlines, blurred-word paragraphs, hover ripple, velocity skew, project cards rising, hero letter weight near the cursor, footer letters, process cards, FAQ answers, cursor ring and card spotlight
  - **v4 layer:** typewriter kicker, outline headings filling, image wipes, process rail, floating page-hero illustrations, contact form cascade, events deck (pinned), events hover trail, gallery filters and viewer
  - testimonials controller
  - fixed controls (rails, floating CTA visibility)
  - final `ScrollTrigger.refresh()` after fonts load

## `main.css` structure
- **Design tokens on `:root`:** `--bg`, `--bg-2`, `--bg-3`, `--ink`, `--ink-2`, `--muted`, `--line`, `--line-2`, `--accent` (#FEA41E), `--accent-text`, `--accent-em`, `--gutter`, `--nav-h`, fonts.
  - Light mode is `html[data-mode="light"]`. A small script in `<head>` sets `data-mode` from `localStorage['cx-mode']`; the default is dark.
  - Inverted sections use `data-theme="light"` with the `--inv-*` tokens.
- **Sections, in file order:**
  - type, buttons, loader, cursor and grain, nav, hero, marquee, manifesto, light sections, stats, work, process, reasons, FAQ, page heroes, contact, footer
  - motion states (styles that apply only when JS runs: `.js …`)
  - responsive, projects, events and gallery, client logos, testimonials
  - fixed controls (`.rail`, `.tswitch`, `.fab*`; the rails only appear at ≥1200px)
- **Rules that must stay:**
  - `html` and `body` both have `overflow-x: clip`.
  - `.chars` and `.wave` are `position: relative`, so sr-only text can't cause sideways scroll on mobile.

## Hard-won rules (bugs already fixed: don't reintroduce)
- **Elements with CSS opacity or transform:** use `gsap.fromTo()` with explicit end values, not `gsap.from()`. Otherwise they can stay invisible or offset.
- **CSS translate plus a GSAP yPercent tween** makes them add up; include `y: 0` in the from-vars.
- **Process cards (sticky stack):** a card dims only from the moment the next card touches its bottom edge until the next card is stuck (`start: top <stickyTop + cardHeight>px`, `end: top <nextStickyTop>px`). Starting at `top bottom` dimmed the card the visitor was still reading. Their entrance must not animate opacity, or they rise into view dark.
- **Pinned sections need `refreshPriority`:** reel 3, work 2, deck 1. A wrong order makes pins overlap and block clicks.
- **The loader is hidden with visibility, not removed.** Removing it caused a layout-shift (CLS) score of 1.
- **Marquees need exactly 2 identical sets** for a seamless loop.
- **Performance:**
  - One-shot reveals use IntersectionObserver, not one ScrollTrigger each.
  - Lenis stays off on touch devices.
  - Rails logic only runs at ≥1200px.
  - The rails' "on light section" class goes on the rails, not on `<html>` (it caused full-page restyles).
- **Image wipes:** after `clearProps`, set `clipPath: 'none'` in onComplete, or the CSS fallback hides the image.
- **Grid items** holding horizontal scrollers need `min-width: 0` and `minmax(0, 1fr)`. The testimonials thumbnails broke the mobile layout before this fix.

## QA routine before handing back
Tools: `scripts/linkcheck.mjs`, `scripts/qa-sweep.mjs` (overflow + JS errors on every page, both widths) and `scripts/qa-scroll-shots.mjs` (visitor-style scroll screenshots). Usage is in `../AGENT-HANDOFF.md` §8; the Arabic/RTL rules are in §6.

1. `node build.mjs`, then `node serve.mjs`.
2. Load every page at 1440×900 and 390×844, scrolling to the bottom. Check for console errors, and that `document.documentElement.scrollWidth` is not wider than the viewport.
3. Check dark and light mode, and `prefers-reduced-motion`.
4. Lighthouse:
   - Accessibility, Best Practices and SEO were 100 on the tested pages.
   - Mobile performance on the home page is around 70–80, because of the heavy motion.
   - Desktop performance is higher.
- **Never edit `main.js` with a script that uses `String.replace` and a replacement containing `$$`**: in a replacement string `$$` becomes `$`, which turned `$$('.tcard')` into `$('.tcard')` and stopped every module after it (an error inside the async setup is silent). Use a direct edit, or a replacement function.
- **Mouse effects on touchscreen laptops:** test `.has-mouse` (set by `whenMouse()` on the first real mouse movement), not `(any-hover: hover)`, which those laptops report as false.
